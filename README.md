# 📦 部署上传包 · 使用说明（零基础上手）

> 这个文件夹里的东西，是给"云平台"看的。你不需要看懂里面的代码，
> 只要按下面说的，把整个文件夹传到 GitHub，剩下的云平台会自动处理。

---

## 一、这个文件夹里都有啥？

| 文件 / 文件夹 | 它是什么 | 你要管它吗 |
|---|---|---|
| `app.py` | 后台程序的"大脑" | ❌ 不用管，上传就行 |
| `static/` | 装整个手机界面的盒子 | ❌ 不用管，上传就行 |
| `static/index.html` | 手机APP的全部界面（记账、情侣同步都在这） | ❌ 不用管 |
| `requirements.txt` | 清单，告诉云平台要装哪些零件 | ❌ 不用管 |
| `Procfile` | 一句话，告诉云平台怎么启动 | ❌ 不用管 |
| `render.yaml` | 部署配置单，云平台照着它自动搭好 | ❌ 不用管 |
| `.gitignore` | 排除表，告诉上传时哪些东西不用传 | ❌ 不用管 |
| `README.md` | 就是你现在看的这份说明 | ❌ 不用管 |

**一句话总结：里面 8 样东西你一个都不用改、不用看懂，整包上传即可。**

## 二、上传时要注意的"树形结构"

GitHub 上文件夹长这样才对（⚠️ 关键是 `static` 是**文件夹**，`index.html` 要**放进** `static` 里面）：

```
xiaomiqian-dai   ← 你的仓库名（随便起，比如 xiaoqian-dai）
│
├── app.py
├── requirements.txt
├── Procfile
├── render.yaml
├── .gitignore
├── README.md
│
└── static          ← 这是一个文件夹！
     └── index.html
```

> 如果 `index.html` 被放到了最外层（跟 `app.py` 并列），打开网页就会白屏。
> 记不住也没关系：**整包上传时保持原样，就不会错**。

## 三、三步走（详细图文看 `部署图文教程.html`）

1. **注册 GitHub**（代码仓库，免费）→ 新建一个仓库
2. **上传**：把本文件夹里所有内容原样传上去（网页拖拽即可）
3. **注册 Render**（云服务器，免费）→ 用 `render.yaml` 一键部署
   → 部署完给你一个网址，比如 `https://xiaoqian-dai.onrender.com`

最后：你和她各自用手机浏览器打开这个网址 → 你点"创建家庭"拿到 **6 位邀请码** → 她输邀请码加入 → **以后你俩记的账就自动同步了**。

## 四、情侣版都能干啥？

| 功能 | 说明 |
|---|---|
| 👫 共同账本 | 默认账本，双方记的账自动合并、互相同步 |
| 🔒 个人私账 | 记账时切到"我的私账"，只存自己手机，不传给对方 |
| 🏷️ 昵称标记 | 每笔账会显示"谁记的"，明细页可以按人筛选 |
| 📊 贡献榜 | 情侣账本页显示本月两人各花了多少、各记了几笔 |
| ☁️ 同步状态 | 顶栏小图标实时显示：已同步 / 同步中 / 离线 / 未连接 |
| 📵 离线补偿 | 断网也能正常记账，联网后自动补传 |
| 🗑 删除同步 | 一方删掉某笔账，另一方那边也会跟着消失 |

## 五、关于"免费"要说清楚的事

- Render 免费版**15 分钟没人访问就会打盹**，下次打开需要等 30～60 秒"唤醒"，属正常现象，数据不会丢。
- 数据存在 Render 提供的 **1GB 永久硬盘**上（`render.yaml` 里已配好），重启也不会丢。
- 两个人日常记账，1GB 够用非常非常久（几百万条记录都装得下）。

## 六、技术细节（想了解再看，不看也不影响使用）

**接口**

```
POST /api/household/create  {nickname, emoji, color}   → 返回邀请码
POST /api/household/join    {inviteCode, nickname}     → 加入家庭
GET  /api/household/state   ?hh=&me=&since=            → 成员 + 增量记录
POST /api/sync              {hh, me, since, changes[]} → 合并并返回增量
GET  /api/health                                       → 健康检查
```

**同步原理**：每条记录带全局唯一 `syncId` 和毫秒级 `updatedAt`；客户端把本地改动推给服务端，服务端按"时间新的赢"（LWW）合并，再返回游标之后的新数据。删除用"墓碑队列"记录后推送，保证对方也能删掉。

**本地跑起来（会电脑的人用）**

```bash
cd xiaomiqian-dai-server
PORT=8080 python3 app.py
# 浏览器打开 http://localhost:8080/
```

依赖：`fastapi`、`uvicorn`。数据存在 `data.db`（SQLite 单文件）。
